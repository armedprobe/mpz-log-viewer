## Контекст

См. `proposal.md` — Зачем. Просмотрщик уже умеет преобразовывать `ProcessElement` в сырые строки лога (`GuiApp.computeProcessLines()`). Функция экспорта переиспользует это преобразование и записывает результат в новый файл.

Существующие соглашения проекта:
- Ввод-вывод файлов сосредоточен в `FileService` (фоновые потоки с seq-защитой)
- Хелперы таблиц принимают `Consumer`-коллбэки для действий
- Диалоги сохранения используют `javafx.stage.FileChooser`
- Директория по умолчанию — последняя использованная из `GuiSettings`

## Цели / Не-цели

**Цели:**
- Добавить кнопку экспорта в центральный тулбар (после кнопки отмены), видимую, когда процесс выделен
- Записывать сырые строки лога выбранного процесса в `.log`-файл в исходном порядке
- Диалог сохранения с именем по умолчанию `<имя_исходного_файла>-<PID>.log`
- Переиспользовать `GuiApp.computeProcessLines()` для получения строк
- `FileService.exportToFile()` выполняет фактическую запись (в потоке-демоне, чтобы UI оставался отзывчивым при больших объёмах)

**Не-цели:**
- Пакетный экспорт нескольких процессов (только один процесс)
- Пользовательская фильтрация строк или выбор формата
- Индикатор прогресса экспорта (запись файла достаточно быстра для ожидаемых размеров логов)
- Экспорт из представления с фильтром по ошибкам (всегда экспортируются полные строки процесса)

## Решения

| Решение | Выбор | Рассматривавшиеся альтернативы |
|---|---|---|
| **Где разместить экспорт** | Кнопка в центральном тулбаре, после кнопки отмены | Контекстное меню: лишний клик; только кнопка — проще и заметнее |
| **Как получать строки** | Использовать данные модели `byPid`.`getLines`.`getEntry` | Дублирование логики преобразования: нарушает DRY |
| **Как записывать файл** | Новый метод `FileService.exportToFile()` в потоке-демоне | Запись в FX-потоке: блокирует UI для больших файлов; отдельный утилитарный класс: `FileService` — естественное место |
| **Санитизация имени файла** | Замена символов, недопустимых в именах Windows (`<>:"/\|?*`), на `_` | Без санитизации: может не сохраниться; полное удаление: теряет информацию |
| **Подключение коллбэка экспорта** | Action на кнопке в `GuiApp` напрямую: `exportProcess(selectedProcess, stage)` | Коллбэк через `ProcessTableHelper`: не нужно, контекстного меню нет |

## Риски / Компромиссы

- **[Риск] Большой процесс (100k+ строк) синхронно пишется в потоке-демоне** → `exportToFile` уже работает вне FX-потока; диалог сохранения возвращается до начала записи, поэтому задержка неощутима
- **[Риск] Коллизия имени файла по умолчанию** → Пользователь может изменить имя в диалоге сохранения перед подтверждением
- **[Риск] Не-ASCII символы в имени процесса** → Java `FileWriter` / `Files.writeString` поддерживает UTF-8; имя файла использует системную кодировку по умолчанию, но SaveDialog корректно отображает его на современных версиях Windows

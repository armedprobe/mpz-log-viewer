## Context

Текущее приложение на JDK 8 использует тему JMetro через 4 статических CSS-файла, загружаемых через `scene.getStylesheets().add(...)`. Java-код не содержит вызовов JMetro API. Кастомные стили в `app.css` (318 строк) используют хардкод-цвета `#hex`.

AtlantaFX 2.1.0 требует JavaFX 17+ (из-за `data-url` в CSS) и собирается под JDK 21. Предоставляет тему PrimerLight с системой looked-up color variables на базе GitHub Primer.

## Goals / Non-Goals

**Goals:**
- Заменить JMetro на AtlantaFX PrimerLight
- Поднять JDK до 21 и JavaFX до 22
- Сократить `app.css` с 318 до ~55 строк, убрать все хардкод-цвета
- Сохранить всю существующую функциональность без изменений поведения
- Убрать inline-стиль `setStyle("-fx-font-weight: bold")`

**Non-Goals:**
- Переключение тем в рантайме (тёмная/светлая)
- Использование дополнительных контролов AtlantaFX (TabLine, SegmentedControl и т.д.)
- Изменение компоновки окна
- Создание собственной SASS-темы

## Decisions

### D1: AtlantaFX как Maven-зависимость, а не статические CSS

**Выбор**: Добавить `io.github.mkpaz:atlantafx-base:2.1.0` в `pom.xml`.

**Альтернатива**: Скачать скомпилированный CSS с GitHub Releases и встроить статически (как JMetro сейчас).

**Обоснование**: Maven-зависимость даёт автоматическое обновление версии, BSS-компиляцию тем (быстрее загрузка), и Java API для установки темы (`new PrimerLight().getUserAgentStylesheet()`). Статический CSS требует ручного обновления и поиска правильного пути.

### D2: PrimerLight как единственная тема

**Выбор**: Использовать `PrimerLight`, не добавлять переключатель тем.

**Альтернатива**: Добавить несколько тем на выбор (PrimerDark, Nord, Cupertino).

**Обоснование**: Пользователь явно сказал «переключение тем излишне». PrimerLight — светлая тема с современным «воздушным» стилем, что соответствует запросу. При желании добавить тёмную тему позже — это одна строка `setUserAgentStylesheet`.

### D3: Установка темы через Application.setUserAgentStylesheet()

**Выбор**: Вызывать `Application.setUserAgentStylesheet(new PrimerLight().getUserAgentStylesheet())` в `GuiApp.start()` до создания Scene.

**Текущий подход**: `scene.getStylesheets().add(...)` с JMetro CSS.

**Обоснование**: `setUserAgentStylesheet` заменяет Modena глобально — все контролы сразу получают AtlantaFX-стили. `getStylesheets().add` добавляет CSS поверх существующей темы, что создаёт конфликты и требует больше переопределений. Пользовательский `app.css` всё ещё подключается через `getStylesheets().add` как слой кастомных стилей поверх.

### D4: Удаление JMetro CSS-файлов целиком

**Выбор**: Удалить все 4 JMetro-файла из `src/main/resources/gui/`.

**Обоснование**: Файлы не используются ни одним другим компонентом, не нужны для обратной совместимости. Хранение мёртвого кода не имеет смысла.

### D5: Минимальный app.css — только компоновка и псевдоклассы

**Выбор**: Оставить в `app.css` только:
1. Фоны и границы панелей компоновки (`.left-panel`, `.center-panel`, `.bottom-panel`)
2. Паддинги тулбара и статус-бара
3. Псевдокласс `:active-process`
4. Скрытие горизонтального скроллбара таблицы процессов
5. Моноширинный шрифт для областей кода
6. Оверлей загрузки

Всё остальное (выделение строк, наведение, заголовки, диалоги, кнопки) — зона ответственности AtlantaFX.

**Обоснование**: AtlantaFX полностью стилизует стандартные контролы. Переопределять их цвета и шрифты — значит бороться с темой. Исключения — только то, что является частью уникальной компоновки приложения (панели, псевдоклассы) или функциональным требованием (моноширинный шрифт для кода).

### D6: Перенос inline-стиля в CSS

**Выбор**: Убрать `displayModeLabel.setStyle("-fx-font-weight: bold;")` из `MainLayoutBuilder.java`, добавить правило `.toolbar-label:bold` или аналогичное в `app.css`.

**Обоснование**: AGENTS.md запрещает inline-стили. Это последний оставшийся случай — устраняем.

## Risks / Trade-offs

- **AtlantaFX меняет внешний вид ВСЕХ контролов** (скругления, отступы, шрифты) — может потребоваться подгонка размеров колонок таблиц. → Проверить TableView после миграции, при необходимости скорректировать `setPrefWidth` в `ProcessTableHelper`.
- **JDK 21 может изменить поведение `java.util.prefs.Preferences`** на Windows — `GuiSettings` полагается на Windows Registry. → Preferences API стабилен десятилетиями, риск минимален.
- **launch4j с JDK 21** — плагин 2.5.2 может не поддерживать JDK 21. → Проверить при сборке, при необходимости обновить версию плагина.
- **Иконка `✕` (U+2715) на кнопке Cancel** — может рендериться иначе с новым системным шрифтом AtlantaFX. → Проверить визуально, при необходимости заменить на текст «Сброс».

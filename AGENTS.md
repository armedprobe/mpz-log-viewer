# MPZ Log Viewer — Agent Context

## Project Overview

Утилита для чтения и анализа лог-файлов МПЗ (MpzLog). Парсит структурированные логи Java-приложения, выделяет процессы МПЗ и позволяет фильтровать/просматривать их.

**Сборка:** Maven, Java 8+ (target 1.8, совместимо с Java 11)
**Структура:**
- `CliParser.java` — парсинг CLI-аргументов
- `ModeOptions.java` — хранилище опций режима
- `App.java` — точка входа
- `mode/ModeHandler.java` — интерфейс режима
- `mode/ModeContext.java` — контекст для режимов
- `mode/ModeFactory.java` — фабрика, выбирающая режим по `ModeOptions`
- `mode/AnalyzeMode.java` — режим `-a` (по умолчанию): сводка + ошибки по процессам
- `mode/GrepMode.java` — режим `-g`: поиск процессов по тексту
- `mode/ListProcessesMode.java` — режим `-lp`: список процессов
- `mode/ProcessMode.java` — режим `-p`: записи конкретного процесса + итог
- `parser/MpzLogParser.java` — парсер лога
- `parser/LogEntry.java` — модель записи лога
- `parser/ProcessAnalyzer.java` — анализатор процессов МПЗ
- `ui/TerminalPrinter.java` — вывод в консоль и файл

## CLI Arguments

| Флаг | Описание |
|------|----------|
| `-h`, `--help` | Справка |
| `-a`, `--analyze` | Сводная информация о логе (по умолчанию) |
| `-p`, `--process <id>` | Показать записи процесса МПЗ |
| `-g`, `--grep <text>` | Поиск процессов по тексту в записях |
| `-lp`, `--list-processes` | Список процессов МПЗ |
| `-of`, `--output-file` | Сохранить вывод в файл (плоский текст) |

Для режима `-g` выходной файл имеет суффикс `_<текст>_строка.txt`, где символы, недопустимые в именах файлов (`<>:"/\|?*` и контрольные символы), заменяются на `_`.

Если не указан ни один режим, по умолчанию используется `-a`.

## ProcessAnalyzer — Алгоритм

### Формат лога МПЗ

Записи процесса МПЗ выглядят так:
```
... handle-request: <?xml...><process-instance>0</process-instance>...
... handle-response: <?xml...><process-instance>XXXXX</process-instance>...
```

Процесс начинается с `handle-request` где `<process-instance>=0`. Ответ содержит реальный PID процесса.
Если процесс не может определить PID (ошибка), ответ также содержит `process-instance=0`.
Повторный вызов к уже известному процессу: `handle-request` с `process-instance=<PID>`.

### Алгоритм (один проход + active-трекинг)

Единственный проход по всем записям. Для каждого трека поддерживается «активный процесс».
Каждая запись атрибутируется активному процессу своего трека.

- **`handle-request pi=0`**: создать новый `ProcessInfo` (pending). Если на этом треде уже был завершённый процесс, у нового pending сохраняется `parentId`. Новый pending становится активным на треде.
- **`handle-request pi!=0`**: если процесс с таким PID уже известен, он становится активным на треде. Повторный запрос к тому же процессу — все последующие записи (включая логи и ошибки) попадают в него.
- **`handle-response pi!=0`**: завершить pending: установить `pid`, добавить в `processes`. Активный процесс сбрасывается.
- **`handle-response pi=0`** (ошибка подзапроса):
  - Если на треде есть pending с `parentId` — все его накопленные записи перемещаются в родительский процесс.
  - Иначе запись атрибутируется текущему активному процессу (если есть).
- **Обычные записи** (не handle): атрибутируются активному процессу трека.

### Особенности

- Несколько процессов на одном треде: новый `handle-request pi=0` создаёт новый pending, старый pending заменяется в `startByThread`. Если старый был завершён (имел PID), новый pending получает его ID как `parentId`.
- Если подзапрос успешен (`pi!=0`), он становится отдельным процессом в `processes`. Если провалился (`pi=0`), все его записи переходят родителю.
- `parentId` используется для передачи записей провалившегося подзапроса родительскому процессу.

## AnalyzeMode — формат вывода

```
═════════════════════════════════════════════
 MPZ Log Viewer
═════════════════════════════════════════════
  Процессов МПЗ: <N>
  Всего строк: <N>
  Критических ошибок: <N>
  Время парсинга: <N> мс

═════════════════════════════════════════════
  Часто встречающиеся ошибки          ← только если criticalErrors > 0
═════════════════════════════════════════════
<exception-message> — <N> раз(а)

═════════════════════════════════════════════
  Ошибочные процессы МПЗ:            ← только если criticalErrors > 0
═════════════════════════════════════════════
Process: <PID> (<process-name>)
<timestamp> <LEVEL> (<thread>) <exception-message>
  <ORA-...>
  <at by.softclub.mpz....>            ← стек до первого non-mpz вызова
─────────────────────────────────────────────
Process: <PID> (<process-name>)
...
```

В блоке «Часто встречающиеся ошибки» каждая уникальная ошибка выводится один раз с общим количеством.

## Сборка и запуск

```bash
mvn clean package
java -jar target/mpz-log-viewer.jar mpz.log          # анализ (по умолчанию)
java -jar target/mpz-log-viewer.jar mpz.log -lp      # список процессов
java -jar target/mpz-log-viewer.jar mpz.log -p 8092830 -of  # процесс в файл
java -jar target/mpz-log-viewer.jar mpz.log -a -of   # анализ в файл
java -jar target/mpz-log-viewer.jar mpz.log -of      # анализ в файл (режим определяется по умолчанию)
```

## Известные ограничения

- Для процессов с `pi=0` в response (ошибка) — две записи с `pi=0` (request и response)
- Вывод в консоль на Windows может не отображать кириллицу (зависит от кодировки терминала)
